# تشخيص التحقق من نتائج البحث

عندما يعيد النموذج إجابة، لم تصبح بعد نتيجة موثقة. تظهر رسالة
`Agent returned an answer; validation pending` قبل فحص JSON والمصادر والاستشهادات.
لا يُجهّز محتوى التقرير للحفظ إلا بعد نجاح التحقق.

عند الرفض تعرض الطرفية سببًا عربيًا ورمزًا ثابتًا مثل
`[validation:missing_numbered_citation]`.
يحمل حدث `research_finished` في سجل المهمة داخل `.runtime/traces/` الحقول
`status` و`reason=output_validation` و`error_code` و`source_count`.
لا يُحفظ نص الإجابة المرفوضة أو رسالة الاستثناء الخام أو مفاتيح الوصول.

| الرمز | المعنى |
|---|---|
| `unsupported_output_shape` | الناتج ليس نصًا أو كتلًا نصية مدعومة |
| `invalid_output_schema` | تعذّر تحويل الناتج إلى الحقول الأربعة المطلوبة ضمن حدودها |
| `no_usable_evidence` | لا توجد مصادر صالحة في سياق المهمة؛ لا يثبت ذلك عدم وجود دراسات |
| `missing_sources` | قائمة مصادر الإجابة فارغة رغم توفر أدلة في السياق |
| `unretrieved_source` | مصدر الإجابة ليس ضمن الأدلة المسترجعة |
| `unsupported_summary_url` | رابط داخل الملخص ليس ضمن الأدلة المسترجعة |
| `missing_numbered_citation` | الملخص العلمي لا يحتوي على استشهاد مثل `[1]` |
| `citation_out_of_range` | رقم الاستشهاد لا يقابل عنصرًا في قائمة مصادر الإجابة |
| `invalid_numbered_citation` | صيغة رقمية غير مدعومة مثل `[1-99]`؛ تُفحص مجموعات `[1، 2]` بالكامل |
| `invalid_cleaned_result` | فشل التحقق النهائي بعد تنقية النص وإضافة التنبيهات |

إذا لم تتوفر أدلة، يعرض النظام أيضًا أخطاء الخدمات المسجلة، إن وجدت.
قد توجد بيانات ورقة بلا ملخص، لكنها لا تصلح دليلًا لتلخيص نتائجها.
يبقى منع حفظ الإجابة غير المتحققة قائمًا. لا توجد إعادة محاولة مدفوعة تلقائية
لإصلاح JSON أو الاستشهادات.

## توحيد المراجع بأمان

إذا سجّلت طبقة إزالة التكرار مسبقًا رابطين للورقة نفسها داخل `context.aliases`،
يوحّد التحقق رابط المصدر والرابط الموجود داخل الملخص إلى الرابط المعتمد المسترجع.
عند دمج المصادر المكررة، يعيد ترقيم الاستشهادات بما يحفظ ارتباط كل رقم بورقته.
مثلًا: المصادر `[A, A_alias, B]` والاستشهادات `[1], [2], [3]` تصبح
`[A, B]` والاستشهادات `[1], [1], [2]`.

تمنح الأدلة العلمية ذات الملخص معرفًا ثابتًا مثل `P1` في `source_id`.
يمكن للنموذج وضع هذه المعرفات في `sources`؛ يحولها التطبيق إلى الروابط الأصلية
قبل إرجاع الحقول العامة أو إعداد التقرير. يشير `[1]` إلى أول عنصر في قائمة
`sources`، بغض النظر عن الرقم داخل المعرف `P2` مثلًا.

تُقبل اختلافات HTTP وHTTPS في روابط arXiv المعروفة، والرابط دون رقم نسخة،
إذا أمكن ربطه بدليل واحد غير ملتبس. لا تُقبل نسخة صريحة مختلفة عن النسخة
المسترجعة. يمكن حل رابط DOI من بيانات DOI المسترجعة إلى صفحة الورقة الأصلية.
تبقى الروابط النهائية هي روابط الأدلة الأصلية، ولا تنفذ هذه المعالجة طلب شبكة.
لا تُقبل المعرفات المجهولة أو أوراق بلا ملخص أو نطاقات مشابهة أو روابط ذات
معاملات إضافية باعتبارها بدائل علمية. قواعد توحيد الهوية لا تشمل روابط الويب العامة.
الاستشهادات المفقودة أو خارج النطاق تظل مرفوضة.
التحقق يثبت وجود المرجع ضمن الأدلة المتاحة وصحة ترقيمه؛ لا يضمن وحده أن كل
ادعاء في الإجابة تدعمه دلاليًا جملة محددة من الملخص العلمي.

إذا رُفض عنصر من `sources`، تسجل الآثار `source_index` (موضعه بدءًا من 1)
و`source_issue` (`unknown_source_reference` أو `metadata_without_abstract`)،
دون نسخ المرجع المرفوض أو نص الإجابة الخام إلى السجل.

## الاختبارات المحلية

من مجلد المشروع في PowerShell:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_validation.py -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_source_identity.py -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

الاختبارات الجديدة تحظر الشبكة وتستخدم بيانات اصطناعية معلّمة، ولا تشغّل أبحاثًا حقيقية.
تُكتب آثارها في `.runtime/tests/` ولا تُعرض كسجلات نجاح حية.

## حدود إصلاح الاختبارات السابقة

Q3 وQ4 انتهتا سابقًا بـ`invalid_response` دون حفظ الناتج الخام أو قاعدة الرفض.
لا يمكن تحديد سبب رفضهما بدقة بأثر رجعي أو تأكيد إصلاحهما بهذا الاختبار المحلي.
Q5–Q7 لم تحصل على أدلة بسبب تعطل/رفض/تقييد خدمات البحث.
هذا التغيير يوضح السبب ولا يصلح توفر الخدمات الخارجية أو إعداد مفاتيح Asta.
تحتاج إعادة التشغيل الحية إلى موافقة منفصلة وضمان بقاء ميزانية التطبيق ضمن حدودها.
