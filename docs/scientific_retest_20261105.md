# إصلاح مراجع البحث العلمي وإعادة الاختبار — 5 نوفمبر 2026

## نطاق العمل

إصلاح مطابقة الاستشهادات وإعادة الأسئلة العلمية السبعة نفسها عبر CLI الحقيقي
باستخدام `.venv` و`gpt-6-luna` و`--mode scientific --verbose`.
لم تُستخدم محاكاة في الجولة الحية، ولم تُعدّل حدود الميزانية أو الجولات أو
الإخراج، ولم تُقرأ مفاتيح أو ملفات `.env` يدويًا. سمح مسار CLI المعتاد بتحميل
إعدادات التطبيق فقط. لا حزم جديدة ولا تنزيلات اعتماديات.

## التغيير

- تمنح الأوراق ذات الملخص معرفات داخلية ثابتة مثل `P1` في `source_id`.
  يُطلب من النموذج نسخها؛ يحوّلها التطبيق إلى روابط الأدلة الأصلية قبل عرض
  الحقول العامة أو تجهيز التقرير، مع بقاء ترقيم الاستشهادات مرتبطًا بترتيب `sources`.
- تُحل اختلافات HTTP/HTTPS وصور DOI من هوية مسترجعة فعلًا. يقبل رابط arXiv
  دون رقم نسخة عند عدم الالتباس، لكنه يرفض نسخة صريحة مختلفة عن نسخة الدليل.
  أضيف بعد الجولة الحية تحصين إضافي لهذه القاعدة عند المرور عبر جدول إزالة
  التكرار، واختُبر محليًا؛ لم تُنفذ جولة مدفوعة أخرى لهذا التحصين.
- لا تُقبل أوراق بلا ملخص، أو معرفات مجهولة، أو نطاقات مشابهة خادعة، أو
  روابط غير معروفة. لا تُجرى طلبات شبكة لتخمين المراجع أو إصلاحها.
- تسجل أخطاء المصادر موضع العنصر وسببًا ثابتًا، دون حفظ المرجع المرفوض أو
  إجابة النموذج الخام. بقيت صلاحية تأكيد حفظ التقارير كما هي.

الملفات: `main.py`, `research_models.py`, `scientific_tools.py`, `tracing.py`,
`tests/test_source_identity.py`, `docs/validation_diagnostics.md`، وهذا التقرير.
تعديل `budget.py` وملفات اختبار حد السياق يعود للمهمة السابقة.
