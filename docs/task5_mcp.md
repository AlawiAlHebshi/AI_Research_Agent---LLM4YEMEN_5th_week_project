# المهمة 5 — Exa وAsta MCP

تاريخ التحقق: 5 نوفمبر 2026. هذه المهمة لا تشمل SQLite أو Streamlit أو النشر أو مرحلة الأمان النهائية.

## ما يعمل

- `exa_search` أداة الويب الأساسية، بعد اجتياز فحص MCP حي: مصافحة، اكتشاف، بحث واحد، وخمسة مصادر.
- `duckduckgo_search` باقية، وتُجرّب تلقائيًا إذا أخفق Exa أو عاد دون نتائج؛ Wikipedia باقية أيضًا.
- `search_asta` تُعرض في النمط العلمي فقط عند وجود `ASTA_TOOL_KEY`. غياب المفتاح لا يعطّل المصادر الثلاثة الأصلية.
- عند تعثر Semantic Scholar: محاولة Asta إن كان معدًا؛ ثم OpenAlex إذا لم يُرجع Asta ملخصات قابلة للاستخدام.
- نتائج Asta تمر في `PaperRecord` وإزالة التكرار والاستشهادات وترقيم المراجع الحالية. أوراق بلا ملخص لا تدخل قائمة أدلة الإجابة.
- الحفظ ما زال محليًا بعد موافقة الإنسان، وبمحتوى التقرير المتحقق فقط.
- حلقة النموذج المتزامنة وقياس التوكنات والحجز وحدود $0.03/$0.30/$5 وعدد الجولات لم تتغير.

## طريقة الربط

`mcp_client.py` عميل Python محدود يعتمد على `requests` المثبتة. لا يحتاج Node أو SDK أو تنزيل tokenizer.
كل بحث MCP يتكون عادة من أربعة POST: `initialize`، ثم `notifications/initialized`، ثم `tools/list`، ثم `tools/call`.
يدعم JSON وSSE واستمرار معرف الجلسة وترويسة إصدار البروتوكول. الإصدارات المقبولة هي `2025-03-26` و`2025-06-18` و`2025-11-25`؛ أي إصدار آخر يتوقف بخطأ واضح.
ليس هذا عميل MCP عامًا: لا يدعم stdio أو OAuth أو sampling أو elicitation أو استئناف SSE أو طلبات الخادم لتنفيذ عمل محلي.
لا يعيد المحاولة تلقائيًا، ولا يتابع تحويلات HTTP. لا يستخدم `.netrc` أو وكلاء الاتصال من متغيرات البيئة؛ الشبكات التي تتطلب proxy تحتاج مراجعة منفصلة.
حد الاستجابة 1MB، ومهلة اتصال 5 ثوان وقراءة 15 ثانية، وفحص مدة قراءة 25 ثانية أثناء استقبال القطع.
هذه ليست مهلة جدارية تقطع كل اتصال قسرًا. حد 180 ثانية الحالي للوكيل يُفحص بين خطواته كما سابقًا.
هناك حد عشرة عمليات بحث MCP داخل السياق الواحد؛ يُفتح اتصال MCP جديد لكل استعلام، ولا يُعاد الاتصال الفاشل تلقائيًا.
الجلسات البعيدة لا يُعاد استخدامها ولا تُنهى بطلب DELETE؛ تُغلق اتصالات HTTP، ويُترك انتهاء حالة الجلسة للخادم.

لا تُمرر أوصاف الأدوات البعيدة إلى النموذج؛ يرى أغلفة الأدوات المحلية المراجعة فقط.
الأداة البعيدة الوحيدة المسموحة لـExa هي `web_search_advanced_exa`، ولـAsta هي `search_papers_by_relevance`.
السبب هو أن الأداة البسيطة تعيد نتائج كنص منسق؛ النسخة المختارة تعيد JSON يفصل حقول روابط المصادر عن نص المقتطفات.
لا نعرض الخيارات المتقدمة للنموذج: نثبت `numResults=5` و`enableHighlights=true` و`enableSummary=false` فقط.
لا تُقبل عناوين `Title/URL` أو روابط داخل المقتطفات كمصادر مستقلة، حتى لو قلدت شكل نتائج الخادم.
لا تُفعّل قراءة صفحات كاملة أو PDF أو مقتطفات متن الورقة أو `agent_run` أو أدوات كتابة بعيدة.
Exa مجهول الهوية عمدًا: لا يُرسل أي مفتاح Exa حتى لو كان موجودًا في البيئة، ولا يُفعّل حساب مدفوع.
مفتاح Asta يُقرأ في ذاكرة التطبيق عند الطلب ويرسل فقط إلى عنوان Ai2 المحدد، ولا يُسجل.

## ما تحقق فعلًا

التحقق النهائي المحلي: **96 اختبارًا ناجحًا = 69 اختبارًا سابقًا + 27 اختبار MCP جديدًا**.
نجح `pip check` برسالة `No broken requirements found` وظهرت خيارات CLI الجديدة في `--help`.
فشل اختبار تكامل أولي لأن حارس الميزانية رفض اسم Exa الجديد؛ أُضيف الاسمان المعتمدان إلى قائمتي نمطيهما دون تعديل سقوف التكلفة أو السماح بأدوات عشوائية، ثم نجحت المجموعة كاملة.

1. فحص Exa داخل العزل أخفق قبل استلام بيانات: `connection_failed`، محاولة HTTP واحدة، صفر بايتات.
   السجل: `.runtime/traces/4cc6ef4d938b404f8c809b3c9b219901.jsonl`.
2. تكرار الفحص نفسه مرة واحدة خارج عزل الشبكة نجح: أربعة طلبات HTTP، بحث فعلي واحد، خمس نتائج، 16,339 بايت من أجسام الاستجابات.
   السجل: `.runtime/traces/00008156e03d4bb2ba71604a227ac838.jsonl`.
3. فحص النسخة النهائية ذات JSON بعد تحسين فصل المصادر عن المقتطفات نجح أيضًا: أربعة طلبات HTTP، بحث واحد، خمس نتائج، 20,610 بايت.
   السجل: `.runtime/traces/14a338023a0e4cafaed96d595f93048d.jsonl`.
4. فحص Asta توقف محليًا بـ`asta_key_missing`: صفر طلبات شبكة؛ المتغير غير متاح في البيئة الموروثة، ولم نقرأ `.env` لتجاوزه.
   السجل: `.runtime/traces/259adac6ae4846e781d45d203517c8a9.jsonl`.

السجلات موسومة `public_tool_probe` وليست نجاحًا كاملًا للوكيل ولا بديلًا لسجلات الكابستون.
النتائج الحية لـExa تضمنت وثائق MCP الرسمية وإعلان Anthropic.
لم يُجرَ أي طلب OpenAI حي، ولم يُختبر بحث Asta حيًا. نجاح Asta في الاختبارات المحلية يعتمد على بيانات اصطناعية معلنة.
لم يُختبر التشغيل الحقيقي الكامل (المصادر ثم التلخيص بالنموذج) في هذه المهمة؛ يتطلب إذن OpenAI منفصلًا.

## التشغيل والاختبار بنفسك

افتح PowerShell في مجلد المشروع، واستخدم البيئة الموجودة دون تثبيت حزم.

### اختبارات محلية دون شبكة أو رصيد

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p test_mcp.py -v
.\.venv\Scripts\python.exe -B main.py --help
.\.venv\Scripts\python.exe -I -m pip --isolated --disable-pip-version-check check
```

الاختبارات تستخدم النموذج وHTTP ببيانات وهمية، وتحظر socket؛ لا تحمل `.env`.
قد تظهر تحذيرات لحالات فشل مقصودة؛ الحكم هو `OK` في النهاية.
تغطي مصافحة JSON/SSE، تحديد الأدوات، الجلسة، المهلات، 401/403/429/503، التحويلات، حجم الاستجابة، ومنع طلبات الخادم.
وتغطي نتائج Exa والتحقق من الروابط والتعافي مع DuckDuckGo، وAsta والتكرار والاستشهادات وغياب المفتاح والتعافي مع OpenAlex.
تختبر أيضًا حلقة LangChain المتزامنة بالميزانية، ورفض الحفظ بعد MCP، وعزل أنماط البحث.
لا تحذف آثار الاختبارات ولا تصفّر سجل الإنفاق الحقيقي.

### فحص MCP حقيقي دون OpenAI

```powershell
.\.venv\Scripts\python.exe -B scripts/check_mcp_sources.py --source exa
.\.venv\Scripts\python.exe -B scripts/check_mcp_sources.py --source asta --query "retrieval augmented generation education"
```

كل أمر تجربة مستقلة. المتوقع عند النجاح: `status: ok`، عدد نتائج أكبر من صفر، `openai_requests: 0`، ومكان JSONL.
الفحص لا يجرب مزودًا آخر ولا يُجري بحث DuckDuckGo تلقائيًا، حتى تبقى الطلبات محدودة ومعروفة.
فحص Asta يحتاج `ASTA_TOOL_KEY` في بيئة العملية؛ لا يحمّله من `.env`. أعدّه بنفسك من إعدادات متغيرات البيئة في Windows، ثم افتح terminal جديدًا.
لا تضع قيمة المفتاح في أمر مسجل ولا ترسلها للمحادثة. لا ترسل مفتاح OpenAI إلى Asta.
الحصول على مفتاح Asta يكون عبر رابط الطلب الرسمي في صفحة Ai2، ولا نفعّل خدمات مدفوعة.
غياب المفتاح يعطي `asta_key_missing` دون إرسال طلب. رفضه من الخادم يعطي `access_denied`؛ لا تغيّر المفاتيح أو تكرر الاختبار تلقائيًا.
Exa المجاني قد يرفض الشبكات ذات IPv6 أو proxy أو يحدّ معدل الطلبات. لا تتجاوز تلك القيود؛ استخدم البديل أو وثّق الخطأ.

### تشغيل الوكيل الحقيقي — يستخدم رصيد OpenAI

الأوامر التالية للمستخدم بعد اختياره إجراء تجربة مدفوعة، ولم ينفذها Codex في هذه المهمة.

```powershell
.\.venv\Scripts\python.exe -B main.py --budget-status
.\.venv\Scripts\python.exe -B main.py --mode web --query "What is Model Context Protocol, and what are its main uses?" --verbose
.\.venv\Scripts\python.exe -B main.py --mode web --web-provider duckduckgo --query "What is renewable energy?"
.\.venv\Scripts\python.exe -B main.py --mode scientific --query "What do paper abstracts report about retrieval-augmented generation in education?" --verbose
.\.venv\Scripts\python.exe -B main.py --mode web --query "Explain Model Context Protocol with sources." --save mcp_report.txt
```

تأكد من أن الإجابة تستشهد بنتائج الأدوات فعلًا، وأن `tools_used` يعكس أسماء الأدوات المحلية الحقيقية (`exa_search` و`search_asta` مثلًا).
النمط العلمي لا يُجبر الوكيل على استخدام كل المصادر؛ لذلك عدم استدعاء Asta في سؤال واحد لا يعني أن الربط معطل.
إذا كان Asta غير معد تظهر رسالة بذلك، ويستمر البرنامج بالمصادر الأصلية.
طلب الحفظ لا يكتب أثناء البحث؛ بعد عرض التقرير اكتب `n` لرفضه أو `y` لحفظ التقرير المتحقق داخل `reports`.
تعثر DuckDuckGo القديم لم يُصلح؛ يبقى بديلًا مؤقتًا وقد تتعافى المهمة عبر Wikipedia.

## الموارد والحدود

لا حزم مثبّتة أو محدّثة أو منزّلة في هذه المهمة. فُحص pip wheel cache محليًا، وأُعيد استخدام `requests` الموجودة.
عدد استدعاءات OpenAI الحقيقية صفر، واستهلاك توكناته وتكلفته الحقيقية صفر.
فحوص MCP: محاولة Exa فاشلة وثمانية طلبات ناجحة؛ بحثا Exa فعليان، وصفر طلبات Asta. لا مفتاح Exa ولا خدمة مدفوعة.
مجموع أجسام الاستجابات المستلمة 36,949 بايت؛ لا يشمل ترويسات HTTP/TLS أو تصفح الوثائق أو حركة الإنترنت الكلية.
ميزانية التطبيق تقيس OpenAI ولا تقيس رسوم مزودي بحث جدد؛ لذلك لا يتيح هذا الربط حساب Exa مدفوعًا.
المصدران Asta وSemantic Scholar قد يعيدان الورقة نفسها؛ لا يُحسب ذلك مصدرين بفضل إزالة التكرار الحالية.
